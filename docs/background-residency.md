# Mate XTs / HarmonyOS 7 后台运行方案

目标是切换应用、回桌面、锁屏后，代理及 WireGuard 家庭访问继续可用。验收以业务请求、握手和加密收发为准。

## 当前版本

0.3 已安装：Go 内核与 TUN 由独立 VpnExtensionAbility 承载，界面不参与转发；有服务存活期间的网络切换重建。用户在其他应用确认家庭 IP/域名均已恢复，正常重启后重连家庭 DNS 再次通过。

0.3 尚未申请数据传输长时任务，尚未通过长期后台与锁屏验收。已验证签名包保留在 `.deps/releases/0.3.0/`。以下是下一版实施方案，不表示功能已经交付。

## 0.4 定位辅助驻留候选

按用户要求加入设置开关“定位辅助驻留（实验）”，默认关闭，旧配置迁移也保持关闭。代码已实现并通过本机 SDK 签名构建与模拟 SDK 的控制器测试，尚未安装或确认真机效果。

- 仅用户开启开关时申请 `APPROXIMATELY_LOCATION`；未申请精准位置或“始终允许”后台位置权限。LOCATION 长时任务与前台模糊位置权限的组合需在目标手机验证。
- 连接 VPN 时，由 EntryAbility 的 UIAbilityContext 订阅低功耗定位（请求间隔 60 秒）并申请 LOCATION 长时任务，使用系统通知与返回的任务 ID。该任务属于 UI 进程；VPN 扩展是另一个进程，不能从 UI 任务申请成功直接推出整个 VPN 已获得驻留保障。
- 定位回调不读取 Location 的任何字段，不存储、输出或上传坐标。仅请求低功耗策略，实际耗电由系统与运行环境决定。
- 断开、暂停、拒绝 VPN 授权、关闭开关、定位权限撤回、关闭系统定位时释放订阅与任务；连接尚未成功时最多等待 90 秒。后台状态通过系统 VPN 双栈地址核对，避免仅依赖过期心跳。
- 启动/停止操作串行执行；关闭或断开会使正在申请的任务失效，晚到的成功结果也立即清理。系统取消后不自动反复申请；用户可重新连接或切换开关。系统挂起、恢复、取消及错误码分别显示。
- 此方案会使用定位资源并可能增加耗电。它是用户明确要求的自用实验，不能视为应用商店适用性结论，也不能承诺系统强停或极端省电后自动复活。

待真机项：首次权限及通知、重复开关与断开后的资源释放、静置锁屏 30 分钟、整夜 8 小时、Wi-Fi/蜂窝切换、耗电对照。基准组为同一配置且开关关闭，实验组开启；两组都不持续发送测试流量维持活跃。

参考 [华为定位服务团队关于前台位置权限与 LOCATION 长时任务的说明](https://developer.huawei.com/consumer/cn/forum/topic/0201198953402329041)，并核对 API 26 `geoLocationManager` 与 `backgroundTaskManager` 声明。数据传输长时任务及 WorkScheduler 仍是下文的待实现项。

## VPN 会话与长时任务

1. TUN、内核、WireGuard、物理网络绑定由 VPN 扩展管理。切换页面和应用不清理隧道；明确断开或系统销毁扩展时释放资源。
2. 用户连接时，由 EntryAbility 的 UIAbilityContext 申请 DATA_TRANSFER 长时任务及可见通知，声明对应 backgroundModes 和 KEEP_BACKGROUND_RUNNING 权限。SDK 限定由 UIAbility 申请，不能直接传 VPN 扩展 Context。
3. 使用系统返回的 notificationId/continuousTaskId 管理本次会话。通知显示真实状态与累计收发字节，点击打开 App；不含节点、家庭地址或凭据，不伪造没有业务依据的进度百分比。
4. 数据传输长时任务有进度更新要求，超过十分钟不更新可能取消，低速时也可能挂起。因此它是稳定性增强措施，不能独立证明空闲 VPN 永久存活。记录真实申请、取消、挂起、恢复事件与错误码；界面区分 VPN 状态和后台任务状态。
5. 权限拒绝或申请失败时明确提示。用户取消通知、断开或启动失败后清理任务；不自动重复申请来对抗用户操作。重复连接不得遗留通知和任务。

## 资源与恢复

- UI 退后台后停止展示快照，保留 VPN 必要网络监听；降低空闲磁盘心跳与重复日志，前台恢复实时显示。
- 状态结合系统 VPN 网络及双栈地址核对，避免仅因 JS 心跳过期就误报 native 隧道停止。配置与节点选择独立持久化。
- 网络恢复后释放旧内核/TUN，再绑定新物理 NetID 重建。进程已结束时，普通定时器没有进程外拉起能力；用户重开 App 后核对系统 VPN，按已保存的自动连接设置恢复。
- 设置页提供当前手机的电池/应用启动管理说明，由用户决定系统后台活动许可。真机核对菜单后固定说明，App 自身开关不能冒充系统豁免。

## 订阅更新

使用 WorkScheduler 持久化延迟任务，有网络时择机检查到期配置，单次在系统两分钟窗口内结束，停止回调取消后续提交。它不负责 VPN 保活，也不保证准点。沿用 0.3 私有锁、不可变版本和提交冲突检查；更新不热替换运行中的隧道。

## 真机验收

| 场景 | 通过条件 |
| --- | --- |
| 退桌面、切其他 App | 家庭 IP/域名与双栈代理可访问，通知对应真实会话 |
| 锁屏空闲 30 分钟 | 无调试亮屏、USB供电或持续探测；解锁后先访问业务，再打开 App |
| 夜间锁屏 8 小时 | 次日首次业务访问可用，记录握手、耗电和进程状态 |
| 正常流量与超过十分钟空闲 | 区分持续流量与低速挂起，验证真实通知和回调 |
| Wi-Fi/蜂窝切换、暂时无网 | 旧路由释放，新 NetID 重建，家庭 DNS/IP 恢复 |
| 关闭 UI、移除最近任务 | 分别实测是否结束扩展，不将两种操作视为相同 |
| 拒绝权限、断开、取消通知、系统强停 | 无反复拉起，任务释放，状态及恢复入口清晰 |
| 省电、内存压力 | 记录系统干预，不承诺普通签名无限常驻 |

SDK 构建通过不能替代上述验收。现在无需持续连接手机，候选完成后再安排真机测试。

## 核对依据（2026-10-25）

- [华为：后台任务合理使用](https://developer.huawei.com/consumer/cn/doc/doccenter-app-quality/bpta-use-of-background-tasks)：长时、延迟任务的区别与运行约束。
- [华为：长时任务](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/continuous-task)：公开开发入口，实施细节同时核对本机 SDK。
- API 26 `@ohos.resourceschedule.backgroundTaskManager.d.ts`：UIAbility Context 限定、十分钟进度要求、低速挂起、取消/恢复回调、任务 ID。手机 TASK_KEEPING/特殊场景依赖受限 ACL，当前签名未获得该能力。
- 同一 SDK 的 WorkScheduler 与 WorkSchedulerExtensionAbility 声明：持久登记、系统择机触发、停止回调及两分钟窗口。
