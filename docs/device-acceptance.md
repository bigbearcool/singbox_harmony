## 必须通过的检查

1. **安装和加载**：签名 HAP 安装成功，EntryAbility 可启动，日志出现 `native-core=sing-box 1.14.3`，进程不崩溃。此步骤验证动态库加载和外来线程进入 Go。
2. **双栈 TUN**：连接后读取应用内接口信息，确认系统分配 IPv4 和 IPv6；TUN 名来自运行时查询，路由使用同一名称。`running` 状态仅说明启动和地址检查成功。
3. **实际路由**：用设备可用的网络服务诊断工具确认两条默认路由被系统接纳。若无读取权限，记录观测限制，结合后面的负向流量检查，不能填“通过”。
4. **IPv4 TCP 与 UDP**：从其他应用访问测试服务；在内核配置中加入针对测试目的地址的拒绝规则，确认测试流量会被拦截，排除绕过 TUN。
5. **IPv6 TCP 与 UDP**：使用可控的 IPv6-only 端点重复正向和拒绝规则测试，并在测试服务端核对请求与出口地址。随后让相同测试目标通过指定代理出口，核对服务端看到的出口。
6. **DNS A/AAAA**：系统 DNS 查询指向 TUN 内地址；两种记录均能解析。对可控测试域使用阻断规则确认请求经过核心 DNS，并核对所选 DoH/自定义 DNS 出站。
7. **蜂窝 IPv6**：关闭 Wi-Fi，确认物理蜂窝接口具备 IPv6，重新连接 VPN，重复第 5、6 项。基础网络无 IPv6 的测试环境不能当作蜂窝 IPv6 验收。
8. **生命周期**：断开后网络恢复，连续连接/断开至少 5 次不残留 VPN 或泄漏 fd；拒绝授权、无效配置、失去网络时不出现“已连接”的假状态。
9. **锁屏**：连续通网时锁屏测试，恢复后验证数据面仍在；记录时长、系统电量策略和日志。

请使用自己的可控测试节点与端点。配置中的节点凭据留在应用沙箱，诊断日志仅记录生命周期与非敏感内核版本。
