# Mate XTs / HarmonyOS 7 真机验收

## 2026-10-25 实测记录

- 设备：华为 Mate XTs，系统报告 `GRL-AL20`，HarmonyOS 7 / API 26，arm64-v8a。
- 使用本人生成的 DevEco 调试签名，包名 `com.bigbear.singbox`；已安装并确认系统 VPN 授权。
- 配置：内置直连诊断配置。没有使用用户代理节点或节点凭据。
- 基础网络：蜂窝 `rmnet0`，实际接口存在 IPv6 地址。Wi-Fi 场景未验证。
- 真实 TUN：`vpn-tun`，按 `172.19.0.1` 和 `fdfe:dcba:9876::1` 两个地址共同识别，未猜测接口名。
- 日志确认 `sing-box 1.14.3` 已加载，并在 VPN 进程中运行；公共 NetConn 出站 socket 绑定成功，所观测绑定失败计数为 0。

### 默认路由

VPN ConnectionProperties 返回 `0.0.0.0/0` 与 `::/0`，接口均为 `vpn-tun`。运行时另从 `/proc/net/ipv6_route` 观察到全零目的地址、前缀长度 `00` 的 `vpn-tun` 路由。

配置显式列出两条默认路由，接口与网关字符串为空，由服务填入真实接口。仅设置 `hasGateway:false` 而仍传入 `::` 网关，不能保证本设备路由落地；空路由列表的系统补全也不能代替显式 `::/0`。

### 数据面正向与负向

“检查连接”通过公共 API 把测试 socket 绑定到本应用实际 VPN NetID，排除本应用进程被豁免而直接通网的误判。

| 测试 | 直连诊断配置 | 加入 `::/0` 拒绝规则 |
| --- | --- | --- |
| IPv4 TCP HTTP HEAD → `223.5.5.5:80` | 成功，收到 HTTP 响应 | 成功 |
| IPv6 TCP HTTP HEAD → `[2400:3200::1]:80` | 成功，收到 HTTP 响应 | 未通过 |
| IPv4 UDP DNS A | 成功 | 成功 |
| IPv6 UDP DNS AAAA | 成功 | 成功 |

DNS 每个表格项包含两项查询：IPv4 为 `192.0.2.53` 与 `172.19.0.2`，IPv6 为 `2001:db8::53` 与 `fdfe:dcba:9876::2`。前者是保留文档地址，不运行真实上游 DNS；收到正确事务 ID、成功响应和答案，证明 53 端口被内核截获。后者覆盖系统配置的虚拟 DNS 地址。查询名为 `one.one.one.one`，A 通过 IPv4 UDP、AAAA 通过 IPv6 UDP 发出。此测试未覆盖 IPv6 非 DNS UDP 的远端转发。

负向配置是在直连配置的 `route.rules` 中加入 `{"ip_cidr":["::/0"],"action":"reject"}`。只有 IPv6 HTTP 失败，证明该测试流量进入内核路由。应用强制 DNS 截获规则位于该规则之前，因此负向配置中 DNS 仍成功是预期行为。

### 生命周期

连续 5 轮：连接 → UI 已连接 → 确认 `vpn-tun ::/0` → 断开 → UI 未连接 → 确认该默认路由移除，全部通过。没有据此声称 fd 泄漏或长期运行已经通过压力测试。

最后恢复内置直连诊断配置并断开 VPN；正常启动不再保持窗口亮屏。

## 复现

1. 解锁手机并保持 USB 调试连接，安装签名 HAP。
2. `bash scripts/device.sh launch-test direct`，在 App 中连接并点击“检查连接”，确认四行成功。
3. 断开后 `bash scripts/device.sh launch-test reject-ipv6`，连接并检查，预期只有 IPv6 网页未通过。
4. 断开，使用 `launch-test direct` 恢复内置配置；完成后断开、`stop`、正常 `launch`。

诊断启动仅在 debug 构建生效，不覆盖真实用户配置；临时保持测试窗口亮屏。普通启动不保持亮屏。

HDC shell 曾拒绝 `/proc/net/if_inet6` 和执行 `/data/local/tmp` 程序；未把 native-smoke 标为通过。活动 VPN 的 `/proc/net/ipv6_route` 在本轮可读取，检查依据为签名 App 内自检与该路由观测。原始本机调试输出保存在被 Git 忽略的 `.deps/`，不包含节点凭据。
